P0 级（立即学习，核心能力缺口）

P0-1 委派暂停开关（is_spawn_paused）

Hermes 实现：is_spawn_paused() + delegation.pause RPC

家百星现状：无此机制。一旦 Fanout/Orchestrator 启动，除非全部完成或超时，无法中途冻结。

学习价值：多 Agent 场景下，一个子 Agent 失控可能导致整个 Agent 树资源耗尽。暂停开关是生产环境必备的"紧急刹车"。

实现建议：在 async_delegation.py 的 AsyncDelegator 中增加 _paused: asyncio.Event，每个子任务执行前检查。通过 /api/delegation/pause 和 /api/delegation/resume 端点控制。

预计工时：1天

P0-2 记忆写入审批门（Memory Write Gate）

Hermes 实现：_apply_write_gate / _apply_batch_write_gate

家百星现状：记忆写入无审批，Agent 可以直接修改任何记忆条目。

学习价值：Agent 越自主，越可能产生"记忆污染"——错误推理写入长期记忆，后续对话被污染。审批门让人类可以审查并拒绝不当记忆写入。

实现建议：在 memory/engine.py 的 store_short_term/store_long_term 中增加 _write_gate_enabled 标志。开启时写入暂存到 pending_writes 表，通过 /api/memory/approve 端点批量审批。

预计工时：2天

P0-3 委派角色区分（leaf vs orchestrator）

Hermes 实现：role: "leaf" | "orchestrator" + max_spawn_depth

家百星现状：有委派深度限制，但无角色区分。所有子 Agent 平权，无"叶子节点不可再委派"的约束。

学习价值：角色区分是防止委派树无限膨胀的关键。leaf Agent 专注于执行，orchestrator Agent 专注于编排——职责分离使系统更可控。

实现建议：在 delegate_tool.py 的 DelegateSpec 中增加 role 字段。leaf Agent 调用 delegate_task 时返回错误。

预计工时：1天

P1 级（近期学习，能力增强）

P1-1 技能系统（Skill System + Curator UMBRELLA-BUILDING）

Hermes 实现：Curator 后台维护，三种合并模式（consolidate/prune/archive），仅触碰 agent 创建技能

家百星现状：有 EvolutionEngine 但无 Skill 概念。进化引擎改变的是"策略参数"，而非"可复用技能模板"。

学习价值：技能系统是 Agent 从"每次从零推理"到"积累可复用经验"的关键跃迁。UMBRELLA-BUILDING 自动合并相似技能，避免技能库膨胀。

实现建议：新建 skills/ 模块，技能存储为结构化 JSON（name/description/steps/tools/triggers）。Curator 定期扫描，合并相似度 >0.8 的技能。

预计工时：5天

P1-2 批量原子记忆操作（all-or-nothing）

Hermes 实现：operations 数组，事务性全部成功或全部回滚

家百星现状：记忆写入逐条执行，无事务保证。批量写入中途失败会导致部分写入成功、部分失败。

学习价值：多步推理产生的多条记忆应当原子写入——要么全部生效，要么全部不生效。避免"记住了一半"的脏状态。

实现建议：在 memory/engine.py 增加 store_batch() 方法，使用 SQLite BEGIN/COMMIT/ROLLBACK 事务包裹。

预计工时：1天

P1-3 外部漂移保护（ExternalDriftGuard）

Hermes 实现：ExternalDriftGuard，检测多会话并发写入冲突

家百星现状：无并发写入保护。多会话同时修改同一记忆条目可能导致数据不一致。

学习价值：多平台部署（飞书+微信+CLI）时，同一用户可能从多个入口同时触发 Agent，记忆并发写入是真实风险。

实现建议：在 memory/store.py 的 update() 方法中增加乐观锁（版本号或时间戳比对）。

预计工时：1天

P1-4 记忆快照冻结

Hermes 实现：format_for_system_prompt 在 load 时冻结快照

家百星现状：记忆加载后仍在后台被 Curator 修改，可能导致同一轮对话中记忆内容不一致。

学习价值：对话过程中记忆应保持稳定——加载时冻结快照，本轮对话使用快照，修改在下一轮生效。

实现建议：在 memory/engine.py 的 search_with_context 返回结果中增加 frozen_at 时间戳，结果集返回后不再被 Curator 修改。

预计工时：0.5天

P1-5 SSRF 异步检查

Hermes 实现：async_is_safe_url，异步检查 URL 是否指向内网

家百星现状：网络工具（web_search/web_fetch）有 URL 验证但无 SSRF 专项检查。

学习价值：Agent 可被注入恶意 URL（如 http://169.254.169.254/latest/meta-data/），SSRF 检查是生产环境必备。

实现建议：在 network_tools.py 的 URL 获取前增加 _is_safe_url() 检查，阻止内网/本地/云元数据 IP。

预计工时：0.5天

核心结论

家百星的独特优势（Hermes 不具备）： 反思进化闭环（6层反思 + V1/V2双环）、A2A协议、ToT深度规划、OTel可观测性、金丝雀发布。 这些是家百星的"护城河"——反思+进化是 Hermes 0.17 明确缺失的能力维度。

家百星应向 Hermes 学习的（按优先级）：

  1. P0：委派暂停开关 — 多Agent生产环境必备"紧急刹车"
  2. P0：记忆写入审批门 — 防止Agent记忆污染
  3. P0：委派角色区分 — leaf/orchestrator 职责分离
  4. P1：技能系统 + Curator — 从"每次从零推理"到"积累可复用经验"
  5. P1：批量原子记忆 + 漂移保护 + 快照冻结 — 记忆系统可靠性加固
  6. P1：SSRF 异步检查 — 网络安全防护
  7. P2：Kanban可视化 / Profile Web UI / Cronjob模板 / UIA — 体验增强

关键洞察：家百星和 Hermes 走的是两条不同的演化路线。Hermes 的优势在于"广度"（20+平台、技能系统、委派控制），家百星的优势在于"深度"（反思进化、ToT规划、A2A协议、可观测性）。两者互补而非替代——家百星应学习 Hermes 的"广度"能力，同时保持自己在"深度"上的领先。
