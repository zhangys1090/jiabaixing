二、已修复的关键问题（4 项）

🔴 R-01 · 编排 DSL 条件 eval() 远程代码执行 CRITICAL

位置：python/agent/orchestration/task_dsl.py _parse_line()（原 eval(cond, {"__builtins__": {}}, row)）

问题：DSL branch ... when=<expr> 用 eval 解析条件。即便清空 __builtins__，攻击方可经属性遍历逃逸沙箱：().__class__.__bases__[0].__subclasses__() 即可执行任意代码。若 when= 来自不可信管道定义即构成 RCE。

修复：新增 _compile_dsl_condition()——ast.parse(mode="eval") + 白名单节点校验（仅允许比较/布尔/算术与行字段名引用，禁止 Attribute/Call/Import/Subscript），编译失败即 ValueError，运行时字段缺失安全返回 False。回归测试 test_task_dsl_security.py（9 例，含对 5 种逃逸手法的拒绝断言）。

🔴 R-02 · shell_exec 失败时回退 shell=True HIGH

位置：python/agent/desktop/desktop_controller.py shell_exec()

问题：当 shlex.split 抛 ValueError 时，原代码回退为 subprocess.run(raw_command, shell=True)。危险命令仅用 可绕过的黑名单（"rm -rf /" 等 7 条）校验，而 ; | & $(...) 等 Shell 元字符会被解释执行 → 命令注入。

修复：始终 shell=False；shlex.split 失败（Windows 下用 posix=False 保留路径）即 拒绝执行（fail-closed），绝不回退 shell。黑名单降级为纵深防御。回归测试 test_desktop_controller_shell.py（3 例）。

🟡 R-03 · database.py 表名标识符注入（潜在） MEDIUM

位置：python/agent/persistence/database.py get_table_schema() / get_row_count()

问题：f"PRAGMA table_info({table_name})" / f"SELECT COUNT(*) FROM {table_name}" 直接拼接标识符（SQLite 表名无法参数化）。当前无外部调用方，但属潜在注入点。

修复：新增 _validate_table_identifier()，用 re.fullmatch(r"[A-Za-z_][A-Za-z0-9_]*") 严格白名单校验，非法即 ValueError。

🔴 R-04 · middleware.py 断裂导入（阻塞整个引擎） CRITICAL

位置：python/agent/loop/middleware.py:13

问题：from agent.utils.logger import log, log_ignored —— agent.utils.logger 模块不存在（日志器实际在 agent.core.logger）。该导入失败导致 LoopController → AgentEngine 整条链路 无法 import，全量 pytest 经 conftest 即崩溃。

修复：改为 from agent.core.logger import StructuredLogger, log_ignored 并补 log = StructuredLogger("middleware")，与全项目约定一致。修复后 全量 480 个 agent 模块导入冒烟 0 失败（此前为阻断）。
