# AI智能助手大模型适配架构方案

## 一、核心理念

**AI智能助手作为大模型的"手脚"，需要：**
1. **理解模型能力** - 识别模型支持的功能（文本、图像、工具调用等）
2. **适配模型特性** - 根据模型特点调整prompt格式、参数
3. **发挥模型优势** - 利用模型的最佳能力区间
4. **规避模型弱点** - 处理模型不擅长的情况

---

## 二、架构改进方案

### 2.1 模型能力探测层

```
┌─────────────────────────────────────────────────────────────┐
│                    ModelCapabilityDetector                   │
├─────────────────────────────────────────────────────────────┤
│  detectCapabilities() → {                                   │
│    streaming: boolean,        // 流式输出                   │
│    vision: boolean,           // 图像理解                   │
│    functionCalling: boolean,  // 工具调用                   │
│    maxTokens: number,         // 最大上下文                 │
│    supportedFormats: string[],// 支持的格式                 │
│    preferredPromptStyle: 'chat'|'completion'|'instruct'     │
│  }                                                          │
└─────────────────────────────────────────────────────────────┘
```

**实现要点：**
- 通过API探测模型能力
- 缓存探测结果
- 支持动态切换模型

### 2.2 Prompt模板引擎

```
┌─────────────────────────────────────────────────────────────┐
│                     PromptTemplateEngine                     │
├─────────────────────────────────────────────────────────────┤
│  templates/                                                 │
│  ├── system/                                                │
│  │   ├── base.yaml           # 基础人格                     │
│  │   ├── scene_work.yaml      # 工作场景                    │
│  │   └── scene_comfort.yaml   # 陪伴场景                    │
│  ├── tools/                                                 │
│  │   ├── function_call.yaml   # Function Calling格式        │
│  │   └── react.yaml           # ReAct格式                   │
│  └── multimodal/                                            │
│      ├── vision.yaml         # 图像理解                     │
│      └── document.yaml       # 文档分析                     │
│                                                             │
│  render(templateId, context) → string                       │
└─────────────────────────────────────────────────────────────┘
```

**模板示例 (YAML格式)：**
```yaml
# templates/system/base.yaml
id: base_persona
version: 2.0
variables:
  - name
  - role
  - style
sections:
  - type: system
    content: |
      你是{{name}}，一位{{role}}。
      你的说话风格：{{style}}
      
  - type: memory
    condition: "{{memories.length > 0}}"
    content: |
      【相关记忆】
      {{#each memories}}
      - {{this.content}} ({{this.timestamp}})
      {{/each}}
```

### 2.3 流式响应处理器

```
┌─────────────────────────────────────────────────────────────┐
│                    StreamingResponseHandler                  │
├─────────────────────────────────────────────────────────────┤
│  async *streamGenerate(prompt): AsyncGenerator<Chunk>       │
│                                                             │
│  功能：                                                     │
│  1. 实时返回生成内容                                        │
│  2. 支持中断生成                                            │
│  3. 自动拼接完整响应                                        │
│  4. 错误恢复和重连                                          │
└─────────────────────────────────────────────────────────────┘
```

**集成点：**
- WebSocket实时推送
- 前端打字效果
- 中断控制

### 2.4 Function Calling适配层

```
┌─────────────────────────────────────────────────────────────┐
│                   FunctionCallingAdapter                     │
├─────────────────────────────────────────────────────────────┤
│  tools: [                                                   │
│    { name: "read_file", description: "...", parameters: {} },│
│    { name: "search_code", description: "...", parameters: {}},│
│    { name: "execute_command", description: "...", parameters: {}}│
│  ]                                                          │
│                                                             │
│  convertToPrompt(tools) → string   # 转为prompt格式          │
│  parseToolCall(response) → ToolCall # 解析工具调用           │
│  executeToolCall(toolCall) → Result # 执行并返回             │
└─────────────────────────────────────────────────────────────┘
```

**适配策略：**
- 如果模型支持Function Calling → 使用原生API
- 如果不支持 → 转为ReAct格式prompt

### 2.5 Token预算管理器

```
┌─────────────────────────────────────────────────────────────┐
│                     TokenBudgetManager                       │
├─────────────────────────────────────────────────────────────┤
│  配置：                                                     │
│  - maxTotalTokens: 4096                                     │
│  - reservedForResponse: 1024                                │
│  - maxForMemories: 800                                      │
│  - maxForSystemPrompt: 500                                  │
│                                                             │
│  allocate(context) → TokenAllocation {                      │
│    systemPrompt: number,                                    │
│    memories: number,                                        │
│    userInput: number,                                       │
│    reserved: number                                         │
│  }                                                          │
│                                                             │
│  truncate(content, maxTokens) → string                      │
└─────────────────────────────────────────────────────────────┘
```

### 2.6 多模态输入处理器

```
┌─────────────────────────────────────────────────────────────┐
│                   MultimodalInputProcessor                   │
├─────────────────────────────────────────────────────────────┤
│  processInput(input) → ProcessedInput {                     │
│    type: 'text' | 'image' | 'audio' | 'mixed',              │

│    metadata: {                                              │
│      imageDescription?: string,                             │

│  - 非视觉模型 → 先用VisionEngine描述，再传入文本            │
└─────────────────────────────────────────────────────────────┘
```

## 三、数据流架构

```
用户输入（文本/图像/语音）
    ↓
┌─────────────────────────────────────────────────────────────┐
│ 1. MultimodalInputProcessor                                  │
│    - 识别输入类型                                            │
│    - 预处理（OCR、语音识别、图像描述）                       │
└─────────────────────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────────────────────┐
│ 2. ModelCapabilityDetector                                   │
│    - 获取当前模型能力                                        │
│    - 决定适配策略                                            │
└─────────────────────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────────────────────┐
│ 3. TokenBudgetManager                                        │
│    - 计算token预算                                           │
│    - 截断过长内容                                            │
└─────────────────────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────────────────────┐
│ 4. PromptTemplateEngine                                      │
│    - 选择合适模板                                            │
│    - 渲染最终prompt                                          │
└─────────────────────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────────────────────┐
│ 5. LLMProvider (增强版)                                      │
│    - 流式生成                                                │
│    - Function Calling支持                                    │
│    - 错误处理和重试                                          │
└─────────────────────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────────────────────┐
│ 6. StreamingResponseHandler                                  │
│    - 实时推送前端                                            │
│    - 解析工具调用                                            │
└─────────────────────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────────────────────┐
│ 7. FunctionCallingAdapter (如果需要)                         │
│    - 执行工具调用                                            │
│    - 返回结果继续生成                                        │
└─────────────────────────────────────────────────────────────┘
```

## 六、与大模型协同的最佳实践

### 6.1 Prompt设计原则

1. **角色设定清晰** - 明确AI的身份和能力边界
2. **任务分解明确** - 复杂任务拆分为简单步骤
3. **输出格式规范** - 指定JSON、Markdown等格式
4. **示例引导** - 提供Few-shot示例
5. **约束条件** - 明确限制和边界

### 6.2 上下文管理原则

1. **相关性优先** - 只保留最相关的记忆
2. **时效性标注** - 标注记忆的时间信息
3. **去重压缩** - 避免重复信息
4. **动态调整** - 根据场景调整记忆数量

### 6.3 工具调用原则

1. **工具描述清晰** - 让模型理解工具用途
2. **参数验证** - 执行前验证参数合法性
3. **结果格式化** - 返回结构化的执行结果
4. **错误处理** - 提供清晰的错误信息

## 七、验收标准

### 功能验收

- [ ] 支持流式响应，首字延迟 < 500ms
- [ ] Prompt模板可配置，支持热更新
- [ ] Function Calling准确率 > 90%
- [ ] Token预算管理，溢出率 < 1%
- [ ] 多模态输入正确处理

### 性能验收

- [ ] 流式响应吞吐量 > 50 tokens/s
- [ ] Prompt渲染时间 < 10ms
- [ ] Token计算时间 < 5ms

### 兼容性验收

- [ ] 支持 OpenAI API 格式
- [ ] 支持 Ollama 格式
- [ ] 支持国产大模型（通义、文心等）
