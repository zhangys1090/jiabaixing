# jiabaixing 交互功能流转测试计划

## 1. 测试目标

验证jiabaixing系统从前端用户访问到后端核心业务流程的完整交互链路，确保：
- 各功能模块间数据传递准确
- 用户操作流程顺畅无阻断
- 异常场景处理得当
- 前后端联动正确

## 2. 测试范围

### 2.1 前端功能模块
- 页面加载与初始化
- WebSocket连接管理
- 消息发送与接收
- 聊天界面渲染
- 快捷操作按钮
- 状态显示（连接状态、Agent执行状态）

### 2.2 后端功能模块
- HTTP API接口
- WebSocket消息处理
- AgentLoop状态机
- 核心推理引擎
- 记忆引擎
- 交互引擎

### 2.3 端到端交互链路
- 用户输入 → 后端处理 → 前端响应
- 异常处理与错误反馈
- 状态同步

## 3. 测试环境

| 组件 | 地址 | 说明 |
|------|------|------|
| 前端 | http://localhost:3100 | React开发服务器 |
| 后端API | http://localhost:3111/api | Express HTTP服务 |
| WebSocket | ws://localhost:3111 | 实时通信 |
| LLM服务 | http://127.0.0.1:8001/v1 | 本地Qwen2.5:3b |

## 4. 测试用例

### 4.1 基础连接测试

#### TC-001: 前端页面加载
- **步骤**: 访问 http://localhost:3100
- **预期**: 页面正常加载，显示欢迎消息
- **检查点**: 
  - 标题显示"jiabaixing"
  - 欢迎消息正确显示
  - 输入框可用

#### TC-002: WebSocket连接建立
- **步骤**: 打开页面后观察WebSocket连接
- **预期**: 成功连接到ws://localhost:3111
- **检查点**:
  - 收到connected消息
  - 连接状态显示正确

#### TC-003: 后端API可用性
- **步骤**: 调用POST /api/process
- **预期**: 返回200状态码和正确响应
- **检查点**:
  - 响应格式正确
  - 中文编码正常

### 4.2 核心交互测试

#### TC-004: 用户消息发送（General意图）
- **步骤**: 发送"你好"
- **预期**: 收到一条LLM生成的回复
- **检查点**:
  - 用户消息显示在聊天区域
  - 只收到一条响应（无重复）
  - 响应内容合理
  - 输入框状态恢复

#### TC-005: 用户消息发送（Development意图）
- **步骤**: 发送"帮我写一个Hello World程序"
- **预期**: 触发file skill执行
- **检查点**:
  - AgentLoop进入执行状态
  - 收到执行结果
  - 参数验证通过

#### TC-006: 用户消息发送（Search意图）
- **步骤**: 发送"搜索一下项目里的配置文件"
- **预期**: 触发search skill执行
- **检查点**:
  - 查询参数正确传递
  - 返回搜索结果

#### TC-007: 用户消息发送（Schedule意图）
- **步骤**: 发送"查看今天的日程安排"
- **预期**: 触发schedule skill执行
- **检查点**:
  - action参数正确
  - 返回日程列表

#### TC-008: 用户消息发送（Command意图）
- **步骤**: 发送"执行命令：ls -la"
- **预期**: 触发command skill执行
- **检查点**:
  - 命令参数正确传递
  - 返回执行结果

### 4.3 异常场景测试

#### TC-009: WebSocket断开重连
- **步骤**: 重启后端服务
- **预期**: 前端自动重连
- **检查点**:
  - 重连机制正常工作
  - 重连后消息发送正常

#### TC-010: 后端服务不可用
- **步骤**: 停止后端服务，发送消息
- **预期**: 显示错误提示
- **检查点**:
  - 错误消息友好
  - 重试按钮可用

#### TC-011: 超长消息处理
- **步骤**: 发送超过1000字的消息
- **预期**: 正常处理或提示过长
- **检查点**:
  - 无崩溃
  - 响应合理

#### TC-012: 特殊字符处理
- **步骤**: 发送包含emoji、特殊符号的消息
- **预期**: 正常显示和处理
- **检查点**:
  - 前端显示正常
  - 后端处理无报错

### 4.4 状态同步测试

#### TC-013: Agent执行状态显示
- **步骤**: 发送需要执行skill的消息
- **预期**: 右侧Agent面板显示执行步骤
- **检查点**:
  - 各阶段状态正确更新
  - 执行时间显示

#### TC-014: 连接状态实时更新
- **步骤**: 观察连接状态变化
- **预期**: 状态变化及时反映
- **检查点**:
  - 在线/离线状态正确
  - 重连状态显示

### 4.5 数据持久化测试

#### TC-015: 聊天记录加载
- **步骤**: 刷新页面
- **预期**: 历史聊天记录恢复
- **检查点**:
  - 消息顺序正确
  - 错误消息已过滤

#### TC-016: localStorage清理
- **步骤**: 清除localStorage后刷新
- **预期**: 显示初始欢迎消息
- **检查点**:
  - 无历史错误消息
  - 初始状态正确

## 5. 测试执行步骤

### Phase 1: 环境准备
1. 确认后端服务运行（端口3111）
2. 确认前端服务运行（端口3100）
3. 确认LLM服务可用（端口8001）
4. 清理浏览器缓存和localStorage

### Phase 2: 基础测试
1. 执行TC-001至TC-003
2. 记录每个测试的结果
3. 标记失败的测试

### Phase 3: 核心交互测试
1. 执行TC-004至TC-008
2. 验证每种意图类型的处理
3. 检查响应内容和格式

### Phase 4: 异常测试
1. 执行TC-009至TC-012
2. 验证错误处理和恢复机制

### Phase 5: 状态同步测试
1. 执行TC-013至TC-014
2. 验证状态更新及时性

### Phase 6: 数据持久化测试
1. 执行TC-015至TC-016
2. 验证数据加载和清理

## 6. 缺陷分类标准

| 级别 | 定义 | 示例 |
|------|------|------|
| P0-致命 | 系统崩溃或核心功能完全不可用 | 服务无法启动、消息发送无响应 |
| P1-严重 | 主要功能异常或数据错误 | 重复响应、参数验证失败 |
| P2-一般 | 次要功能异常或体验问题 | 状态显示延迟、格式问题 |
| P3-轻微 | 界面问题或建议优化 | 文字提示、颜色样式 |

## 7. 测试报告模板

每个测试用例记录：
- 测试编号
- 测试名称
- 执行时间
- 预期结果
- 实际结果
- 测试状态（通过/失败）
- 缺陷级别（如有）
- 截图/日志（如有）

## 8. 风险与依赖

- LLM服务可用性影响响应测试
- 前端缓存可能导致历史错误显示
- WebSocket连接稳定性受网络环境影响
- 端口占用问题
