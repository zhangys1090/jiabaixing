# 交互体验升级计划

## 概述

本计划针对 jiabaixing 系统前端 UI 进行全面升级，解决当前消息状态混乱、缺乏打字机效果、视觉风格不统一等核心问题，打造流畅、优雅、具有人格化特征的聊天交互体验。

---

## Phase 1: 交互体验升级（P0 - 立即执行）

### 1.1 消息状态机重构

**目标**：明确消息从发送到完成的完整状态流转

**当前问题**：
- 消息状态只有 `pending` / `sent` / `failed` / `read`，缺少中间状态
- AI 回复时显示 🤔 图标，但状态管理不清晰
- 用户无法感知消息正在"思考"还是"输入中"

**新状态机设计**：

```
用户消息：idle → sending → sent → [read]
AI 消息：  idle → thinking → typing → sent → [read]
错误：     sending → error → [retrying → sending]
```

**实现步骤**：
1. 在 `src/frontend/src/types/chat.ts` 中扩展 MessageStatus 类型
2. 在 `ChatInterface.tsx` 中重构状态流转逻辑
3. 为每个状态设计对应的 UI 表现

**状态与 UI 映射**：

| 状态 | 用户消息表现 | AI 消息表现 |
|------|-------------|------------|
| `sending` | 气泡半透明 + 发送中动画 | - |
| `thinking` | - | 显示"正在思考..." + 脉冲动画 |
| `typing` | - | 打字机效果逐字显示 |
| `sent` | 正常显示 | 正常显示 |
| `error` | 红色边框 + 重试按钮 | 错误提示 + 重新生成按钮 |

### 1.2 打字机效果实现

**目标**：AI 回复逐字显示，增强"正在输入"的感知

**技术方案**：
- 使用 `useEffect` + `setInterval` 实现逐字显示
- 支持加速显示（用户点击可立即显示全部）
- 中文按字显示，英文按词显示

**核心组件**：`TypewriterText`

```typescript
interface TypewriterTextProps {
  text: string;
  speed?: number;        // 每个字符间隔(ms)，默认 50ms
  onComplete?: () => void;
  onCharacterTyped?: () => void;
}
```

**交互细节**：
- 打字过程中显示闪烁光标 `|` 
- 打字完成后光标消失
- 用户发送新消息时，自动完成当前打字

### 1.3 消息气泡与视觉优化

**目标**：区分用户/AI 消息，添加时间戳，统一视觉风格

**设计方向**：
- **用户消息**：右对齐，深色背景（主色调），圆角 16px
- **AI 消息**：左对齐，浅色背景，带头像，圆角 16px
- **时间戳**：显示相对时间（"刚刚"、"5分钟前"），hover 显示绝对时间
- **头像**：AI 使用固定头像，用户可自定义

**CSS 变量定义**：

```css
:root {
  --user-bubble-bg: #4a90d9;
  --user-bubble-text: #ffffff;
  --ai-bubble-bg: #f5f5f5;
  --ai-bubble-text: #333333;
  --thinking-bg: #fff8e1;
  --error-bg: #ffebee;
  --border-radius: 16px;
  --spacing-xs: 4px;
  --spacing-sm: 8px;
  --spacing-md: 16px;
  --spacing-lg: 24px;
}
```

### 1.4 错误重试机制

**目标**：网络失败时优雅降级，提供重试入口

**实现步骤**：
1. WebSocket 连接断开时显示"连接中..."状态条
2. 消息发送失败时，消息气泡变红，显示重试按钮
3. 实现指数退避重连：1s → 2s → 4s → 8s（最大 30s）
4. 重试次数限制：最多 3 次

**错误类型处理**：

| 错误类型 | 用户提示 | 自动行为 |
|---------|---------|---------|
| 网络断开 | "网络连接中断，正在重连..." | 自动重连 |
| 发送超时 | "发送超时，点击重试" | 显示重试按钮 |
| 服务器错误 | "服务器繁忙，请稍后重试" | 5秒后自动重试 |
| 消息过长 | "消息过长，请分段发送" | 无需重试 |

### 1.5 Thinking 状态可视化

**目标**：让 AI "思考过程"可见，增强用户信任感

**设计方案**：
- 显示"正在分析..."、"正在回忆..."、"正在生成..."等阶段提示
- 使用渐变进度条或脉冲动画表示思考中
- 思考时间超过 3 秒时，显示趣味提示（"让我想想..."、"这个问题有点意思..."）

## Phase 2: Agent 主动循环增强（P1 - 本周内）

### 2.1 日程检查与提醒

**目标**：每小时检查日程，提前提醒用户

**实现步骤**：
1. 在 `ScenarioAwareScheduler` 中添加 `checkSchedule()` 方法
2. 查询未来 1 小时内的日程
3. 通过 EventBus 发送 `proactive_reminder` 事件
4. 前端显示主动消息（区别于用户触发的回复）

### 2.2 情绪趋势监测

**目标**：分析用户近期情绪，主动关怀

**实现步骤**：
1. 从 `MemoryEngine` 获取近期情绪记录
2. 计算情绪趋势（上升/下降/平稳）
3. 连续 3 天情绪低落时，主动发送关怀消息

### 2.3 早晚简报

**目标**：早上推送日程摘要，晚上推送今日回顾

**实现步骤**：
1. 添加 `MorningBriefingSkill` 和 `EveningReviewSkill`
2. 在特定时间触发（早 8 点、晚 9 点）
3. 生成包含日程、任务、情绪摘要的简报

## Phase 3: 系统稳定性加固（P1 - 本周内）

### 3.1 LLM 调用重试机制

**目标**：避免单次 LLM 失败导致无响应

**实现步骤**：
1. 在 `LLMProvider` 中实现指数退避重试
2. 最大重试 3 次，间隔 1s → 2s → 4s
3. 记录失败日志，供 EvolutionEngine 分析

### 3.2 超时熔断

**目标**：15 秒无响应自动降级

**实现步骤**：
1. 为 LLM 调用设置 15 秒超时
2. 超时后使用本地模板生成降级回复
3. 记录超时事件，触发告警

### 3.3 内存泄漏防护

**目标**：定期清理，防止内存无限增长

**实现步骤**：
1. 限制 `toolCallLogs` 最大 1000 条
2. 限制消息历史最大 100 条（前端）
3. 每小时执行一次内存清理

### 3.4 健康检查端点

**目标**：提供 `/health` 接口供监控

**实现步骤**：
1. 添加 `/health` 路由
2. 检查 WebSocket、MemoryEngine、LLM 连接状态
3. 返回 JSON 格式的健康状态

## Phase 4: 测试体系完善（P2 - 下周）

### 4.1 端到端测试

**目标**：模拟完整对话流程

**测试场景**：
1. 用户问候 → AI 回应
2. 用户告知名字 → AI 记住 → 后续使用名字
3. 用户发送超长消息 → 前端拦截
4. 网络断开 → 自动重连 → 恢复对话

### 4.2 压力测试

**目标**：100 并发连接下的稳定性

**测试指标**：
- 响应时间 P95 < 3 秒
- 内存增长 < 100MB/小时
- 无内存泄漏

### 4.3 前端组件测试

**目标**：React Testing Library 覆盖关键交互

**测试组件**：
- `ChatInterface` — 消息发送、接收、状态变化
- `TypewriterText` — 打字效果、加速、完成回调
- `MessageBubble` — 不同状态的渲染
