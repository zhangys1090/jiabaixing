二、四大补齐建议实施明细

① 多模态 · 真实桌面自动化 + VLM 集成冒烟测试

新增测试：python/tests/test_multimodal_smoke.py（2 用例，均通过）

  • 真实桌面自动化闭环：以真实 PerceptionActionLoop 跑通「定位→截图→执行(桌面点击回调)→验证」闭环，校验接地坐标被正确回传执行（依赖可用时运行，缺失则自动跳过）。
  • VLM 集成：注入 litellm 桩，验证 VLMCaller.analyze / locate_element 走通视觉模型调用链，返回结构化结果。

② 知识沉淀 · 主动从失败学习闭环

新增模块：python/agent/knowledge/failure_learner.py + 接线 LoopController

  • 闭环：主循环失败（工具异常/验证未过/回滚）→ FailureLearner.learn_from_failure → KnowledgeExtractor 写入「纠正知识」→ build_injection_prompt 在 replan 时主动注入历史经验，避免重蹈覆辙。
  • 复用既有 KnowledgeLifecycle / KnowledgeStore，不重复实现记忆写入。
  • 接线位置：controller.py 失败分支触发学习；replan 前注入经验（均 try/except 包裹，不影响主流程）。

③ 安全沙箱 · 高风险动作预检 + 人工审批 + 规划器联动

新增模块：python/agent/safety/risk_precheck.py + 接线 Executor / LoopController

  • 预检层：执行前按工具 risk_level 判定，high/critical 走 ApprovalManager.request_approval（复用运行时安全姿态，critical 永不可自动批准）。
  • 统一入口：Executor._run_tool 替代 3 处直接 registry.execute，未注入预检层时零开销直通。
  • 规划器联动：annotate_plan 为每一步标注风险等级，执行前可展示/确认。

④ MCP · 动态工具发现→LLM选择→执行端到端链路

新增模块：python/agent/mcp/orchestrator.py

  • MCPToolOrchestrator.discover：注册 MCP server 并经既有 MCPToolBridge 桥接到工具注册中心（mcp_<server>_<tool>）。
  • select_and_execute：把注册中心工具定义交给可插拔 ToolSelector（真实 V4 Flash function calling / 离线 RuleBasedSelector），选择后执行回收结果。
  • 仅做编排接线，不重复实现 MCP 连接/工具执行。
