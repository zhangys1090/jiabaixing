## 双重回复（double-reply）根因定位与修复（本轮）

用户反馈：单条"你好"返回两段不同措辞的问候语（双重回复）。逐层排查定位根因并修复。

### 根因（双重叠加）
1. **前端双重订阅**：`ChatContext.tsx` 与 `ChatInterface.tsx`（经 `useWebSocket`→`connectionManager`）**同时**订阅同一 `connectionManager` 的 `response_ready` / `stream_start` / `stream_chunk` / `stream_done` 事件，且两者都 `dispatch({type:'ADD_MESSAGE'})` 到共享 state → 每条事件被渲染 2 次。
2. **单次生成多事件**：服务端 `websocket.ts:processInputOnce` 对同一生成既发 `stream_*` 又发 `response_ready`（均带同一 `traceId`）。前端 `ChatInterface.handleResponseReady` 在流式结束（typingMessageIdRef 已清空）后仍 `ADD_MESSAGE` 一条新消息 → 流式的那条 + response_ready 那条 = 又重复。
3. **历史半成品修复**：上一轮"修双重回复"在 `processInputOnce` 加了死 early-return（"WS 不处理聊天消息"），导致 WS 聊天通道完全断路、无任何回复。

### 修复
- **`ChatContext.tsx`**：删除对 `response_ready`/`stream_*` 的重复订阅（含 handlers、provider 中的 `ensureAssistantMessage` 半成品、无用 `connectionManager` import）。ChatContext 仅持有共享状态。
- **`ChatInterface.tsx`**：引入 `assistantMsgRegistryRef`(Map<traceId,msgId>) + `ensureAssistantMessage(traceId)` 助手，统一渲染——
  - `onStreamStart`：按 traceId 复用/创建一条助手消息（不再每次 `generateMessageId` 新增）。
  - `onStreamChunk`/`onStreamDone`：通过 traceId 取同一条消息追加/收尾。
  - `handleResponseReady`：复用同一条消息 `UPDATE_MESSAGE`（不再 `ADD_MESSAGE`）。
  - `applyAssistantResponse`(HTTP 回退路径)：同样走 `ensureAssistantMessage`，状态置 `sent`。
  - 新增 `spokenMsgIdsRef` 守卫：同一消息只触发一次 TTS，避免 stream_done/response_ready/HTTP 多次收尾重复朗读。
- **`src/server/websocket.ts:processInputOnce`**：删除死 early-return，恢复 WS 聊天经 Python 桥接流式处理（与 HTTP `/api/process` 互斥，前端 WS 连通时只走 WS，断开才回退 HTTP）；`checkAndMarkResponse` 已对重试去重。

### 验证
- 前端 `npx tsc --noEmit`：**0 错误**（受管 Node 22.22.2）。
- 根 TS `npx tsc --noEmit`：websocket.ts / ChatContext 无错误。
