## 一、执行Agent核心定位

### 1.1 什么是执行Agent

执行Agent是能够**自主感知环境、决策行动、执行操作、验证结果**的智能体。与传统对话式Agent的区别：

| 维度     | 对话式Agent          | 执行Agent                                |
| -------- | -------------------- | ---------------------------------------- |
| 核心能力 | 理解、生成、回答     | 感知、决策、执行、验证                   |
| 交互方式 | 文字对话             | 直接操作电脑（鼠标/键盘/窗口）           |
| 任务类型 | 信息查询、写作、分析 | 打开应用、操作界面、处理文件、自动化流程 |
| 闭环模式 | 提问→回答            | 观察→规划→行动→验证→反思                 |
| 自主性   | 被动响应             | 主动执行、自主纠错                       |

### 1.2 执行Agent的核心能力栈

```
┌─────────────────────────────────────────────────────┐
│                  任务理解与分解层                     │
│  自然语言任务 → 结构化步骤 → 操作序列                 │
├─────────────────────────────────────────────────────┤
│                  环境感知层                           │
│  屏幕截图 + 视觉理解 + 窗口识别 + UI元素检测 + OCR    │
├─────────────────────────────────────────────────────┤
│                  决策规划层                           │
│  LLM规划 + 策略选择 + 路径调整 + 错误恢复             │
├─────────────────────────────────────────────────────┤
│                  执行控制层                           │
│  鼠标操作 + 键盘输入 + 窗口管理 + 剪贴板 + Shell      │
├─────────────────────────────────────────────────────┤
│                  验证反馈层                           │
│  结果验证 + 状态检查 + 成功判定 + 反思优化             │
├─────────────────────────────────────────────────────┤
│                  安全管控层                           │
│  权限分级 + 人工确认 + 沙箱隔离 + 操作审计 + 回滚     │
└─────────────────────────────────────────────────────┘
```

### 1.3 放手式操作的核心特征

1. **一句话启动**：用户说"帮我打开Excel整理一下昨天的数据"，Agent自动完成
2. **自主决策**：不需要用户一步步指导，Agent自己判断怎么操作
3. **自动纠错**：操作失败了自己调整策略重试，不用用户干预
4. **结果验证**：做完了自己检查是否成功，有问题自动修复
5. **安全可控**：高风险操作自动暂停请求确认，全程可追溯可回滚

## 四、技术选型

### 4.1 桌面控制库

| 库             | 优点                      | 缺点                    | 推荐度             |
| -------------- | ------------------------- | ----------------------- | ------------------ |
| pyautogui      | 纯Python，跨平台，API简单 | 功能相对基础，无原生OCR | ⭐⭐⭐⭐           |
| pynput         | 轻量，专注输入监听和控制  | 功能较少，需要自己封装  | ⭐⭐⭐             |
| PyWin32        | Windows原生，功能强大     | 仅Windows，API复杂      | ⭐⭐⭐⭐           |
| nut-js（Node） | 功能完善，OCR/模板匹配    | 需要Node环境            | ⭐⭐⭐（TS侧已用） |

**推荐方案**：

- 基础操作：pyautogui（简单易用，跨平台）
- Windows高级功能：PyWin32（窗口管理、进程控制等）
- OCR：pytesseract + Tesseract OCR引擎
- 视觉匹配：pyautogui的locateOnScreen + OpenCV增强

### 4.2 视觉理解

| 方案           | 优点               | 缺点                     | 推荐度     |
| -------------- | ------------------ | ------------------------ | ---------- |
| 多模态LLM API  | 理解能力强，语义化 | 需要网络，有成本         | ⭐⭐⭐⭐⭐ |
| 本地OCR + 规则 | 离线，免费         | 只能识别文字，理解能力弱 | ⭐⭐⭐     |
| 模板匹配       | 精确，速度快       | 只能匹配已知元素，不灵活 | ⭐⭐⭐     |

**推荐方案**：

- 主方案：多模态LLM（GPT-4V / Claude 3 Opus / 豆包多模态）
- 兜底方案：pytesseract OCR + 简单规则
- 辅助方案：模板匹配（用于固定UI元素）

### 4.3 浏览器自动化

**已选方案**：Playwright（已实现）

- 支持多后端：本地、CDP、Browserbase、browser-use
- 功能完善：导航、截图、元素交互、JS执行
- Python/TS都有官方支持

### 5.2 DesktopAgentLoop 循环流程

```
用户输入任务
    │
    ▼
┌──────────┐
│  观察    │ ← 截图 + 窗口列表 + UI元素 + 剪贴板状态
└────┬─────┘
     │
     ▼
┌──────────┐
│  规划    │ ← LLM：任务 + 当前状态 → 动作序列
└────┬─────┘
     │
     ▼
┌──────────┐
│  安全检查 │ ← 风险等级评估 + 权限校验 + 人工确认（高风险）
└────┬─────┘
     │  通过
     ▼
┌──────────┐
│  执行    │ ← 逐个执行动作，每个动作后短暂等待
└────┬─────┘
     │
     ▼
┌──────────┐
│  验证    │ ← 重新观察，判断是否达到目标
└────┬─────┘
     │
     ├─ 成功 → 生成报告，结束
     │
     └─ 失败 → 重试次数 < 上限？
                │
                ├─ 是 → 反思原因 → 调整策略 → 回到观察
                │
                └─ 否 → 报告失败，结束
```

### 5.3 动作体系设计

**基础动作（10+）**：

- 鼠标：click, rightClick, doubleClick, moveMouse, drag, scroll
- 键盘：typeText, keyPress, keyCombo
- 截图：screenshot, screenshotRegion, screenshotWindow
- 窗口：listWindows, activateWindow, closeWindow, maximizeWindow, minimizeWindow

**语义化动作（5+）**：

**高级动作（3+）**：

- openApp(appName)：打开应用
- switchApp(appName)：切换到应用
- closeApp(appName)：关闭应用

## 六、安全设计

### 6.1 风险等级划分

| 等级     | 操作类型      | 处理方式        | 示例                                         |
| -------- | ------------- | --------------- | -------------------------------------------- |
| 低风险   | 只读操作      | 自动执行        | 截图、查看窗口、读取剪贴板                   |
| 中风险   | 可逆操作      | 自动执行 + 记录 | 点击、输入文字、滚动、切换窗口               |
| 高风险   | 不可逆/破坏性 | 人工确认后执行  | 删除文件、格式化、修改系统设置、关闭重要进程 |
| 极高风险 | 系统级破坏    | 直接拒绝        | rm -rf /、格式化磁盘、修改注册表             |

### 6.2 安全门控机制

1. **事前检查**：执行前评估风险等级
2. **人工确认**：高风险操作暂停，等待用户确认
3. **沙箱隔离**：限制可操作的应用和文件路径
4. **操作审计**：记录所有操作，支持追溯
5. **状态快照**：执行前保存状态，支持回滚
6. **紧急停止**：用户可随时中断执行

### 6.3 Manifest 工作空间描述

```python
DesktopManifest = {
    "workspace": "C:\\Users\\xxx\\Desktop",  # 工作目录
    "allowed_apps": ["notepad", "calc", "excel"],  # 允许操作的应用
    "allowed_paths": ["C:\\Users\\xxx\\Documents"],  # 允许访问的路径
    "forbidden_actions": ["format", "del /s", "rm -rf"],  # 禁止的操作
    "max_actions_per_task": 50,  # 单任务最大动作数
    "require_approval_for_high_risk": True,  # 高风险操作需要确认
}
```

## 九、风险与应对

| 风险                                  | 概率 | 影响 | 应对措施                                 |
| ------------------------------------- | ---- | ---- | ---------------------------------------- |
| 桌面操作不稳定（分辨率/DPI/主题差异） | 高   | 中   | 多策略：坐标+图像匹配+语义识别，自动降级 |
| LLM规划不可靠                         | 中   | 高   | 规则兜底+人工确认+多轮修正+验证反馈      |
| 安全问题（误操作）                    | 中   | 极高 | 分级权限+人工确认+沙箱+回滚+审计         |
| 性能问题（LLM调用慢）                 | 中   | 中   | 缓存+快速路径+本地OCR兜底+异步执行       |
| 跨平台兼容性                          | 低   | 中   | 优先Windows，抽象接口，后续扩展          |
