### 1.2 各组件职责说明

#### 主实现（2个）

**1. UnifiedContextPipeline**

- **架构定位**: 上下文系统主实现之一，负责 AI 上下文构建
- **核心职责**: 场景检测、情感分析、时间上下文构建、记忆检索与智能筛选、用户画像构建、数据主权评分
- **在整体架构中的位置**: 用户输入 → ContextReferenceResolver → UnifiedContextPipeline → ConstitutionPromptBuilder → 最终 Prompt
- **使用场景**: 所有交互的上下文构建，集成记忆深度和数据主权

**2. ConstitutionPromptBuilder**

- **架构定位**: 上下文系统主实现之一，负责系统 Prompt 构建
- **核心职责**: 构建完整的 Constitutional 系统提示词、身份定位与人格特质、行为准则与执行纪律、工具清单与使用原则、用户画像动态注入、项目上下文注入
- **在整体架构中的位置**: 用户输入 → ContextReferenceResolver → UnifiedContextPipeline → ConstitutionPromptBuilder → 最终 Prompt
- **使用场景**: 每次对话开始时构建系统提示词、用户画像更新时重新生成、项目上下文变化时更新

#### 辅助组件（5个）

**1. LLMContextBuilder**

- **架构定位**: 上下文系统辅助组件，被 UnifiedContextPipeline 调用
- **核心职责**: 智能记忆筛选、相关性排序、记忆去重、记忆压缩、场景感知权重
- **在整体架构中的位置**: UnifiedContextPipeline → LLMContextBuilder → MemoryEngine
- **使用场景**: 记忆检索后的智能筛选、上下文构建时的记忆优化

**2. ContextFileRegistry**

- **架构定位**: 上下文系统辅助组件，负责项目文件上下文的发现与管理
- **核心职责**: 统一上下文文件发现、优先级管理、安全扫描、文件截断、SOUL.md 独立插槽
- **在整体架构中的位置**: 项目文件 → ContextFileRegistry → ConstitutionPromptBuilder
- **使用场景**: 项目级上下文加载、SOUL.md 人格文件加载、上下文文件安全检查

**3. ContextReferenceResolver**

- **架构定位**: 上下文系统辅助组件，负责用户输入中的 @ 引用解析
- **核心职责**: 解析消息中的 @ 引用（@文件名、@文件夹、@URL、@git_diff）、将引用内容内联展开到上下文中、支持多种引用类型、错误处理与降级
- **在整体架构中的位置**: 用户输入 → ContextReferenceResolver → UnifiedContextPipeline
- **使用场景**: 用户输入中包含 @文件名 引用时、需要将文件内容注入上下文时

**4. ContextWindowManager**

- **架构定位**: 上下文系统辅助组件，负责循环级上下文窗口管理
- **核心职责**: Token 预算管理、工具结果截断、动态上下文压缩、上下文窗口控制
- **与 ContextManager 的分工**: ContextManager 负责会话级上下文构建，ContextWindowManager 负责循环级上下文窗口管理
- **在整体架构中的位置**: ConstitutionPromptBuilder + 对话历史 → ContextWindowManager → 最终 Prompt
- **使用场景**: 主循环每轮的上下文窗口管理、工具执行结果的截断与压缩、不同模型的上下文窗口适配

**5. TokenBudgetAllocator**（已废弃）

- **架构定位**: 上下文系统辅助组件，负责 Token 预算分配（已废弃）
- **核心职责**: 按优先级和比例分配 Token 预算、估算文本的 Token 数（区分中英文）、按预算截断文本
- **状态**: 已标记 deprecated，V6.0 移除
- **替代方案**: Python 端 context_pipeline 中的预算分配

#### 已废弃组件（1个）

**ContextManager**

- **状态**: 已标记 deprecated，V6.0 移除

### 2.2 V1/V2 职责定位说明

#### 双层进化体系架构

```

│                    双层进化体系                          │
│                                                          │
│  ┌───────────────────────────────────────────────────┐  │

│  │  - 完整的规划→验证→执行→回滚流程                  │  │
│  │  - 低频、大幅度的架构级优化                       │  │
│  └───────────────────────────────────────────────────┘  │
│                        ↑                                 │
│  ┌───────────────────────────────────────────────────┐  │
│  │  V1 - 反馈学习层（轻量、快速、低风险）             │  │
│  │  - 从交互反馈中学习，优化参数和 Prompt             │  │
│  │  - 不修改代码，只调整运行时参数                   │  │
│  │  - 实时生效，每次交互都能学习                     │  │
│  │  - 高频、小幅度的参数优化                         │  │
│  └───────────────────────────────────────────────────┘  │
│                        ↑                                 │
│  ┌───────────────────────────────────────────────────┐  │
│  │  EvolutionOrchestrator - 进化编排器               │  │
│  │  - 统一入口，协调 V1 和 V2                        │  │
│  │  - 防止进化冲突                                   │  │
│  │  - 提供统一指标和全局视图                         │  │
│  └───────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

#### V1 - 反馈学习层

**定位**: 轻量、快速、低风险的反馈学习引擎

**核心职责**:

- 收集交互反馈（成功/失败、质量评分、工具使用等）
- 从低质量交互中提取 PromptExample（触发→纠正模式）
- 从工具调用统计中计算进化权重
- 生成策略优化建议
- 识别需要持久化的知识
- 从示例中泛化通用技能

**特点**:

- 轻量：实时运行，性能开销小
- 快速：每次交互都能学习
- 低风险：只修改参数和提示词，不修改代码
- 即时生效：学习结果立即应用

**使用场景**:

- ✅ 工具权重动态调整
- ✅ Prompt 示例积累
- ✅ 用户偏好学习
- ✅ 高频、小幅度的优化
- ❌ 代码修复与优化
- ❌ 架构级变更

**状态**: TypeScript 端已标记 deprecated，V6.0 移除；Python 端继续维护

#### V2 - 自我进化层

**定位**: 重量、深度、高风险的代码级自我进化引擎

**核心职责**:

- 进化规划：根据问题原因生成详细的进化计划
- 自我修改：直接修改代码文件（通过 SelfModificationEngine）
- 回滚机制：进化失败时自动回滚（通过 EvolutionRollback）
- 多类型进化支持：
  - CODE_FIX - 代码修复
  - CODE_OPTIMIZATION - 代码优化
  - PROMPT_IMPROVEMENT - Prompt 改进
  - TOOL_ENHANCEMENT - 工具增强
  - ARCHITECTURE_CHANGE - 架构变更
- 风险评估：对进化操作进行风险等级评估
- 策略学习：记录策略效果，调整策略权重

**特点**:

- 重量：涉及代码修改，执行时间长
- 深度：可以进行架构级别的改进
- 高风险：直接修改代码，可能引入新问题
- 有防护：完整的规划→验证→执行→回滚流程

**使用场景**:

- ✅ 代码修复与优化
- ✅ Prompt 深度改进
- ✅ 工具功能增强
- ✅ 架构级变更
- ✅ 低频、大幅度的优化
- ❌ 实时参数调整
- ❌ 高频小幅度优化

**核心组件**:

- EvolutionPlanner：进化规划器
- SelfModificationEngine：自我修改引擎
- EvolutionRollback：进化回滚机制

**状态**: TypeScript 端和 Python 端均为活跃状态
