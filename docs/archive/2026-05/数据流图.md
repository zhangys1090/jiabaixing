## 二、完整数据流详图（含断点与缺失项）

### 2.1 文本输入链路（CLI 模式）🟢 已通

```
[CLI终端]
    │ 用户输入文本
    ▼
(process.stdin.on 'data')                           🟢 已实现: main.ts:207-212
    │ emit: { text: "帮我创建一个测试文件", source: "text" }
    ▼
[EventBus] (emit 'user_input')                      🟢 已实现: EventBus extends EventEmitter
    │ 监听: EventBus.on('user_input', callback)
    ▼
[SecurityManager.validateInput()]                   🟢 已实现: src/security/SecurityManager.ts
    │ 执行: 注入检测、SQL检测、XSS检测、敏感词检测、长度检测
    │ 返回: { valid: true/false, errors: string[] }
    ▼
    ├─ ❌ valid=false → outputResponse(errors)      🟢 安全拦截输出
    │
    └─ ✅ valid=true
         ▼
    [JiabaixingCore.processInput()]                  🟢 已实现: src/core/JiabaixingCore.ts
         │
         ├── (1) 解析意图: 'greeting' | 'command' | 'question' | 'emotional' | 'chat'
         ├── (2) [🔴断点] MemoryEngine 未注入到 Core
         │       实际代码: Core 内部没有接收 MemoryEngine 的 setter
         │       影响: 无法使用记忆上下文增强决策
         ├── (3) 分发到对应处理器
         └── 返回: response string
         ▼
    [InteractionEngine.outputResponse()]             🟢 已实现: outputResponse() 公共方法
         │
         ├── 生成 Emoji
         ├── 控制台输出: 💝 jiabaixing: {response}
         ├── [🟡缺失] 未触发 TTS（因 source='text'，useVoice=false）
         └── [🟡缺失] 未推送 WebSocket 到前端
```

## 三、断点汇总清单

| #   | 位置                                        | 断点类型 | 严重度 | 原因                                            |
| --- | ------------------------------------------- | -------- | ------ | ----------------------------------------------- |
| 1   | `ContinuousDialogManager.startListening()`  | 🔴 断点  | 高     | 只设置 `isListening=true`，未启动实际音频采集流 |
| 2   | `MockSpeechRecognizer.recognizeStreaming()` | 🔴 断点  | 高     | 返回空结果，无实际语音识别                      |
| 3   | `dialogManager` 不主动调用 recognizer       | 🔴 断点  | 高     | `speechRecognizer` 已注入但从未被使用           |
| 4   | `JiabaixingCore` 未注入 `MemoryEngine`      | 🔴 断点  | 高     | 记忆检索链路完全断开                            |
| 5   | `JiabaixingCore` 未调用 `ToolManager`       | 🔴 断点  | 高     | 工具执行链路断开，无法真正执行操作              |
| 6   | `SpeechSynthesizer.speak()` 无 WS 推送      | 🟡 缺失  | 中     | TTS 播放时未广播音频 chunk 到前端               |
| 7   | 缺少 `broadcastDialogState('PROCESSING')`   | 🟡 缺失  | 中     | 前端无法显示"思考中"状态                        |
| 8   | 缺少 `broadcastDialogState('SPEAKING')`     | 🟡 缺失  | 中     | 前端无法显示"正在说话"状态                      |
| 9   | 前端无音频录制发送能力                      | 🟡 缺失  | 中     | `useWebSocket.send()` 只发 JSON 文本            |
| 10  | 主动提示无 WS 推送                          | 🟡 缺失  | 低     | ProactiveCodeAdvisor 建议不推前端               |
| 11  | 前端无桌面通知                              | 🟡 缺失  | 低     | 未使用 Notification API                         |

## 四、缺失项修复优先级

### P0（核心链路必须修复）

1. **注入 MemoryEngine 到 Core**
   ```typescript
   // main.ts 中添加:
   core.setMemoryEngine(memory);
   // 或在 JiabaixingCore 构造函数中接收
   ```
2. **注入 ToolManager 到 Core**
   ```typescript
   core.setToolManager(tools);
   // Core.processInput() 中当 intent='command' 时调用 tools.execute()
   ```
3. **实现 dialogManager 的音频采集**
   ```typescript
   // ContinuousDialogManager 中:
   // startListening() 需启动麦克风采集 → 传给 recognizer.recognizeStreaming()
   ```

### P1（体验优化）

1. **SpeechSynthesizer 中增加 WS 广播**
   ```typescript
   // speak() 方法中每个音频 chunk:
   broadcastTTSChunk(audioBase64, isLast);
   ```
2. **增加 PROCESSING / SPEAKING 状态广播**
   ```typescript
   // 在 event route 中:
   broadcastDialogState('PROCESSING', round);
   broadcastDialogState('SPEAKING', round);
   ```

### P2（锦上添花）

1. 前端实现音频录制 + blob 发送
2. 主动提示 WS 推送 + 桌面通知
3. EventBus 改为严格类型（当前使用 `unknown`）
