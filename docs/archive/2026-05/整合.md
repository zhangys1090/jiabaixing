# Agent 三大核心组件整合计划

## 概述

本文档详细规划了 Agent 系统中三大核心组件——**大脑（CoreReasoningEngine）**、**记忆（MemoryEngine）**、**交互（InteractionEngine）**——的深度整合方案。整合目标是构建一个具备自主决策、持续学习和拟人化交互能力的统一 Agent 系统，确保组件间高效协同、数据流转顺畅、功能闭环完整。

---

## 一、组件架构与职责定位

### 1.1 三大核心组件

| 组件                            | 核心职责                                             | 关键模块                                                                                  |
| ------------------------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| **大脑（CoreReasoningEngine）** | 意图理解、任务规划、DAG 编排、工具调度、结果校验     | DAGExecutor、DAGTask、ToolExecutor、ToolRecommendationEngine、PriorityArbiter             |
| **记忆（MemoryEngine）**        | 分层记忆存储、语义检索、用户画像、行为模式、反馈信号 | ShortTermMemory、LongTermMemory、VectorDatabase、UserProfile、SemanticSimilarityEngine    |
| **交互（InteractionEngine）**   | 人设一致性、多模态输出、情绪感知、对话管理、主动消息 | PersonaRules、DialogueGenerator、SpeechSynthesizer、EmojiManager、ContinuousDialogManager |

### 1.2 支撑组件

| 组件                       | 职责                         | 整合关系                                       |
| -------------------------- | ---------------------------- | ---------------------------------------------- |
| **EvolutionEngine**        | 反馈采集、策略优化、自动进化 | 接收三大核心组件的反馈信号，输出优化策略       |
| **ScenarioAwareScheduler** | 场景感知、主动调度、任务编排 | 驱动大脑执行主动任务，触发交互引擎发送主动消息 |
| **EventBus**               | 事件总线、持久化、跨模块通信 | 三大核心组件通过 EventBus 进行异步解耦通信     |
| **SkillRegistry**          | 技能注册、发现、执行         | 为大脑提供统一的工具执行接口                   |

## 二、组件间接口设计

### 2.1 接口设计原则

1. **显式契约优先**：所有跨组件调用通过 TypeScript 接口定义，禁止 `any`/`unknown` 类型
2. **异步非阻塞**：核心链路同步执行，辅助操作（记忆存储、反馈采集）异步化
3. **降级容错**：每个接口提供降级方案，确保单点故障不影响整体流程
4. **版本兼容**：接口变更通过版本号管理，向后兼容至少一个版本

### 2.2 大脑 ↔ 记忆 接口

```typescript
// src/interfaces/core-memory.ts
export interface ICoreMemoryBridge {
  /**
   * 检索与当前任务相关的记忆上下文
   * @param query 用户输入或任务描述
   * @param options 检索选项
   */
  retrieveContext(
    query: string,
    options: ContextRetrievalOptions
  ): Promise<MemoryContext>;

  /**
   * 存储任务执行结果到记忆
   * @param taskResult 任务执行结果
   */
  storeTaskResult(taskResult: TaskResultRecord): Promise<void>;

  /**
   * 获取用户画像摘要（用于 LLM Prompt 构建）
   * @param userId 用户ID
   */
  getUserProfileSnapshot(userId: string): Promise<UserProfileSnapshot>;

  /**
   * 存储反馈信号（供进化引擎分析）
   * @param feedback 反馈数据
   */
  storeFeedbackSignal(feedback: FeedbackSignal): Promise<void>;
}

export interface MemoryContext {
  items: MemoryItem[];
  behaviorPatterns: BehaviorPattern[];
  userPreferences: UserPreferences;
  relevanceScore: number;
}

export interface TaskResultRecord {
  traceId: string;
  taskId: string;
  input: string;
  output: unknown;
  toolsUsed: string[];
  success: boolean;
  duration: number;
  timestamp: Date;
  scene: string;
  emotion?: string;
}

export interface UserProfileSnapshot {
  preferredLanguage?: string;
  preferredFrameworks: string[];
  codeStyle?: string;
  namingConvention?: string;
  recentTopics: string[];
  workingHours?: { start: number; end: number };
}
```

### 3.4 数据流转规范

| 数据类型   | 流转方向         | 传输方式      | 序列化格式 | 持久化策略     |
| ---------- | ---------------- | ------------- | ---------- | -------------- |
| 用户输入   | 外部 → 大脑      | EventBus 事件 | JSON       | SQLite 持久化  |
| 记忆上下文 | 记忆 → 大脑      | 接口调用      | 对象引用   | 不重复持久化   |
| 执行结果   | 大脑 → 记忆      | 接口调用      | JSON       | SQLite 持久化  |
| 回复内容   | 交互 → 外部      | EventBus 事件 | JSON       | SQLite 持久化  |
| 反馈信号   | 大脑 → 进化      | 接口调用      | JSON       | SQLite 持久化  |
| 优化策略   | 进化 → 大脑      | 接口调用      | JSON       | 配置文件持久化 |
| 主动消息   | Scheduler → 交互 | EventBus 事件 | JSON       | 可选持久化     |

## 五、整合实施步骤

## 六、关键技术难点及解决方案

### 6.1 难点 1：循环依赖消除

**问题描述**：

- `ScenarioAwareScheduler` ↔ `JiabaixingCore` 双向依赖
- `CoreReasoningEngine` ↔ `InteractionEngine` 潜在循环
- `MemoryEngine` ↔ `EvolutionEngine` 反馈闭环

**解决方案**：

1. **接口隔离**：引入 `ICoreProvider`、`IScheduler` 等接口，依赖接口而非具体实现
2. **事件驱动**：通过 EventBus 进行异步解耦，避免直接方法调用
3. **依赖注入容器**：使用构造函数注入，由 `main.ts` 统一组装依赖图

```typescript
// 改造前（循环依赖）
class Scheduler {
  setCore(core: JiabaixingCore) {}
}
class JiabaixingCore {
  setScenarioScheduler(scheduler: ScenarioAwareScheduler) {}
}

// 改造后（接口解耦）
interface ICoreProvider {
  processInput(input: string): Promise<ProcessInputResult>;
  generateProactiveMessage(context: ProactiveContext): Promise<string>;
}

class ScenarioAwareScheduler {
  constructor(private core: ICoreProvider) {}
}

class JiabaixingCore implements ICoreProvider {
  // 不再持有 Scheduler 引用，通过 EventBus 接收主动任务
}
```

### 6.2 难点 2：EventBus 同步写入阻塞

**问题描述**：

- `EventBus.emit()` 中同步写入 SQLite，高并发下阻塞事件循环
- 持久化操作与事件广播耦合

**解决方案**：

1. **异步批量写入**：使用内存队列缓冲事件，定时批量落盘
2. **写前日志（WAL）模式**：SQLite 已启用 WAL，但emit仍需异步化
3. **优先级分级**：关键事件同步写入，非关键事件异步写入

```typescript
// 改造后
private eventBatch: PersistedEvent[] = [];
private batchTimer: NodeJS.Timeout | null = null;

override emit<T extends EventName>(eventName: T, ...args: EventPayload<T>): boolean {
  if (this.persistentEvents.has(eventName)) {
    this.queueForPersistence(eventName, args); // 仅入队，不写入
  }
  return super.emit(eventName, ...args); // 立即广播
}

private queueForPersistence(eventName: string, args: unknown[]): void {
  this.eventBatch.push({ eventName, args, timestamp: Date.now() });

  if (this.eventBatch.length >= this.BATCH_SIZE) {
    this.flushBatch();
  } else if (!this.batchTimer) {
    this.batchTimer = setTimeout(() => this.flushBatch(), this.FLUSH_INTERVAL);
  }
}
```

### 6.3 难点 3：Skills 系统与 ToolExecutor 整合

**问题描述**：

- `SkillRegistry` 是独立单例，与 `ToolExecutor` 无集成
- `CoreReasoningEngine` 直接调用 `ToolExecutor`，未使用 Skills 接口
- 两套工具系统并存，维护成本高

**解决方案**：

1. **适配器模式**：`ToolExecutor` 实现 `Skill` 接口，作为特殊 Skill 注册
2. **统一入口**：`CoreReasoningEngine` 统一通过 `SkillRegistry` 执行工具
3. **渐进迁移**：保留 `ToolExecutor` 作为降级路径，逐步迁移到 Skills

```typescript
// ToolExecutorSkill 适配器
class ToolExecutorSkill implements Skill {
  definition = {
    name: 'legacy_tool_executor',
    description: '兼容旧版工具执行器',
    category: 'system',
    parameters: [...],
    version: '1.0.0'
  };

  constructor(private toolExecutor: ToolExecutor) {}

  async execute(params: Record<string, unknown>, context?: SkillContext): Promise<SkillResult> {
    const result = await this.toolExecutor.execute(
      params.toolName as string,
      params.toolParams as Record<string, unknown>,
      context?.userId
    );
    return { success: result.success, output: result.data, error: result.error?.message };
  }
}
```

### 6.4 难点 4：记忆检索性能优化

**问题描述**：

- `MemoryEngine` 使用 BM25 + 向量相似度混合检索，计算量大
- 高并发场景下检索延迟高（目标 < 500ms）
- 向量数据库（Chroma）可能不可用

**解决方案**：

1. **分层缓存**：瞬时记忆（内存）→ 短期记忆（SQLite）→ 长期记忆（Chroma）
2. **预计算索引**：启动时预加载热点记忆到内存
3. **降级策略**：Chroma 不可用时使用内存向量 + 哈希嵌入
4. **异步预热**：系统启动后异步预热向量索引

```typescript
// 分层检索策略
async retrieveContext(query: string, options: ContextRetrievalOptions): Promise<MemoryContext> {
  // 1. 瞬时记忆（内存，O(1)）
  const instantResults = this.instantMemory.filter(...);

  // 2. 短期记忆（SQLite，索引查询）
  const shortTermResults = await this.shortTermMemory.retrieve(query, { limit: 10 });

  // 3. 长期记忆（向量检索，异步）
  const longTermPromise = this.vectorDatabase?.searchVectors(embedding, 10)
    .catch(() => this.fallbackVectorSearch(embedding, 10));

  // 4. 合并结果（RRF 算法）
  const longTermResults = await longTermPromise;
  return this.mergeResults(instantResults, shortTermResults, longTermResults);
}
```

### 6.5 难点 5：人格一致性保障

**问题描述**：

- LLM 生成内容可能偏离人设（过于正式、语气不一致）
- 多轮对话后人设漂移
- 复杂任务执行过程中人格表达不连贯

**解决方案**：

1. **System Prompt 强化**：每次请求注入完整人格摘要
2. **后处理校验**：`PersonaRules.adjustTone()` 对输出进行规则校验
3. **模板兜底**：LLM 不可用时使用人设一致的模板回复
4. **一致性评分**：进化引擎监控人格一致性，自动调整 Prompt

```typescript
// 人格一致性保障流程
async function generateWithPersonaConsistency(
  input: string,
  scene: string,
  personaCore: PersonaCore
): Promise<string> {
  // 1. 构建强化 System Prompt
  const systemPrompt = `
你是 ${personaCore.name}，${personaCore.role}。
核心特质：${personaCore.coreTraits.join('、')}。
当前场景：${scene}，语气要求：${personaCore.getToneForScene(scene).description}。
禁止：${personaCore.speechStyle.donts.join('、')}。
  `;

  // 2. LLM 生成
  const rawResponse = await llm.chat(input, [], systemPrompt);

  // 3. 后处理校验
  const validation = personaRules.validate(rawResponse);
  if (!validation.isValid) {
    Logger.warn(`人格校验警告: ${validation.warnings.join(', ')}`);
    return personaRules.adjustTone(rawResponse, scene).adjustedContent;
  }

  return rawResponse;
}
```

### 6.6 难点 6：进化闭环实时性

**问题描述**：

- `EvolutionEngine` 每日凌晨 3 点运行，用户纠错无法立即生效
- 反馈数据积累到 50 条才触发优化，响应慢
- 策略优化后需要重启才能生效

**解决方案**：

1. **实时权重调整**：用户纠错时立即调整工具权重（`adjustWeightLive`）
2. **热加载机制**：优化报告更新后自动应用（`watchAnalysisReport`）
3. **分级触发**：
   - 即时：用户纠错 → 实时权重调整
   - 短期：10 条反馈 → 局部优化
   - 长期：50 条反馈 → 全局优化
4. **偏好记忆快速通道**：纠错直接写入记忆，下次检索立即生效

```typescript
// 实时纠错处理
EventBus.on('user_correction', async (data) => {
  const { toolId, correctionType, reason } = data;

  // 1. 实时调整权重
  const delta = deltaMap[correctionType] || -0.03;
  toolRecommender.adjustWeightLive(toolId, delta, reason);

  // 2. 写入偏好记忆（立即生效）
  await memoryEngine.storeShortTermMemory({
    type: 'user_preference',
    content: `用户纠正: ${toolId} → ${correctionType}`,
    timestamp: new Date(),
    priority: 'high',
  });

  // 3. 触发短期优化（异步）
  if (feedbackCollector.getBufferSize() >= 10) {
    strategyOptimizer.optimizeIfNeeded();
  }
});
```
