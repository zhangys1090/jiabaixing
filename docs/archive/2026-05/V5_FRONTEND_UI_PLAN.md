# Jiabaixing V5.0 前端UI设计规划

> 基于后端V5.0 LLM原生架构的全部功能能力，设计匹配的前端UI方案

---

## 一、现状诊断

### 1.1 后端能力 vs 前端覆盖度

| 后端功能域     | 后端能力                                 | 前端现有组件                | 覆盖度 | 差距                               |
| -------------- | ---------------------------------------- | --------------------------- | ------ | ---------------------------------- |
| **核心对话**   | processInput, FC循环, 直接命令, 澄清提问 | ChatInterface               | 70%    | 缺少FC循环可视化、工具调用链展示   |
| **记忆系统**   | 存储/检索/画像/偏好/知识图谱/关联网络    | 无独立组件                  | 10%    | 严重缺失，需新建MemoryPanel        |
| **进化引擎**   | 四闭环编排/自修复/自重构/自增强/指标     | EvolutionPanel              | 40%    | 缺少四闭环可视化、修复/重构详情    |
| **Agent框架**  | Harness v5/循环控制/约束/验证/持久化     | AgentExecutionPanel         | 35%    | 缺少任务树、约束配置、验证结果     |
| **工具系统**   | 30+工具/推荐引擎/沙箱/权重管理           | SkillConsole                | 50%    | 缺少推荐展示、沙箱状态、权重热力图 |
| **多模态感知** | 情感分析/环境感知/语音/视觉              | VoiceInteraction            | 20%    | 缺少情感仪表盘、环境感知面板       |
| **桌面代理**   | 截图/OCR/UI检查/鼠标键盘自动化           | 无                          | 0%     | 完全缺失，需新建DesktopPanel       |
| **安全模块**   | 输入验证/审计/权限/数据主权              | 无                          | 0%     | 完全缺失，需新建SecurityPanel      |
| **自动化**     | 任务调度/触发器/行为模式                 | AutomationPanel             | 50%    | 缺少触发器编辑器、模式可视化       |
| **系统监控**   | 资源/性能/LLM指标/完整性检查             | PerformancePanel + LogPanel | 40%    | 缺少LLM指标、完整性仪表盘          |
| **人设引擎**   | 性格特征/行为规范/对话风格               | 无独立组件                  | 5%     | 仅在聊天中隐式体现                 |

### 1.2 现有架构问题

1. **单页Tab切换模式**：所有模块通过`activeModule`状态切换，同一时间只能看一个模块，无法同时观察对话+Agent执行
2. **状态管理碎片化**：App.tsx中useState管理10+个状态，缺乏统一Store
3. **WebSocket事件处理集中在App.tsx**：300行代码中大量事件回调，违反单一职责
4. **缺少布局系统**：没有侧边栏、分栏、可拖拽面板等灵活布局
5. **后端能力大量未暴露**：记忆、安全、桌面代理、人设等模块无UI入口

## 二、V5.0 前端UI架构设计

### 2.1 设计原则

| 原则           | 说明                                    |
| -------------- | --------------------------------------- |
| **功能全覆盖** | 每个后端模块都有对应的前端UI入口        |
| **对话为中心** | 聊天界面始终可见，其他面板围绕对话展开  |
| **实时可视化** | FC循环、进化、Agent执行等实时过程可视化 |
| **渐进式披露** | 核心功能直接可见，高级功能按需展开      |
| **契约驱动**   | 所有API/事件引用共享契约层contracts.ts  |

### 2.2 整体布局架构

```
┌──────────────────────────────────────────────────────────────────┐
│  Header: 品牌 + 全局导航 + 连接状态 + 主题切换 + 设置          │
├────────┬─────────────────────────────────────────┬───────────────┤
│        │                                         │               │
│  Left  │           Center                        │    Right      │
│  Rail  │        (主内容区)                        │   (上下文面板) │
│        │                                         │               │
│  导航   │  ┌─────────────────────────────────┐   │  Agent执行    │
│  图标   │  │                                 │   │  面板         │
│  列表   │  │      ChatInterface              │   │               │
│        │  │      (始终可见)                   │   │  或           │
│  💬对话  │  │                                 │   │               │
│  🧠记忆  │  │                                 │   │  Memory       │
│  🤖Agent │  │                                 │   │  Inspector    │
│  🧬进化  │  │                                 │   │               │

└──────────────────────────────────────────────────────────────────┘
```

### 2.3 三栏布局详细设计

#### Left Rail（48px 图标导航栏）

| 图标 | 模块   | 快捷键   | 说明                           |
| ---- | ------ | -------- | ------------------------------ |
| 💬   | 对话   | `Ctrl+1` | 默认激活，中心区域显示聊天     |
| 🧠   | 记忆   | `Ctrl+2` | 右侧面板切换为Memory Inspector |
| 🤖   | Agent  | `Ctrl+3` | 右侧面板切换为Agent执行面板    |
| 🧬   | 进化   | `Ctrl+4` | 右侧面板切换为进化监控         |
| 🔧   | 技能   | `Ctrl+5` | 弹出SkillConsole               |
| 🖥   | 桌面   | `Ctrl+6` | 右侧面板切换为桌面代理         |
| ⚡   | 自动化 | `Ctrl+7` | 右侧面板切换为自动化面板       |
| 🛡   | 安全   | `Ctrl+8` | 右侧面板切换为安全仪表盘       |
| 📊   | 监控   | `Ctrl+9` | 右侧面板切换为系统监控         |

#### Center（主内容区 - 始终显示ChatInterface）

聊天界面是系统的核心交互入口，始终可见。包含以下子区域：

- **消息列表**：支持文本/图片/代码块/工具调用结果
- **FC循环可视化条**：在AI回复上方显示当前FC循环状态（轮次/工具调用数/Token预算）
- **消息输入区**：文本输入 + 图片上传 + 语音按钮
- **VibeCoding浮动层**：澄清请求/执行预览/工具追踪，覆盖在聊天区上方

#### Right Panel（上下文面板 - 可折叠，默认320px）

根据左侧导航选择显示不同面板内容。面板可拖拽调整宽度，可折叠。

## 三、各模块UI详细设计

### 3.1 💬 对话模块 (ChatInterface) — 升级

**现状**：基本聊天功能完整，但缺少FC循环可视化

**升级内容**：

#### 3.1.1 FC循环可视化条

在AI回复消息上方嵌入一个可展开的FC循环状态条：

```
┌─ FC循环 #3/8 ──────────────────────────────────────────┐
│  Token预算: ████████░░ 4200/6000                        │
│  工具调用: file_read ✓ → code_analyze ✓ → code_fix ◉   │
│  耗时: 2.3s | 质量: 0.87                                │
└─────────────────────────────────────────────────────────┘
```

- **数据来源**：WS事件 `brain_stage_update` + `tool_trace` + `agent_execution_update`
- **交互**：点击展开查看每轮FC的详细工具调用和返回结果
- **契约引用**：`WsBrainStageUpdateData`, `WsToolTraceData`

#### 3.1.2 工具调用结果卡片

AI回复中的工具调用结果以卡片形式展示：

```
┌─ 🔧 file_read ────────────────────────┐
│  📄 src/core/JiabaixingCore.ts        │
│  ⏱ 120ms | ✓ 成功                     │
│  ┌──────────────────────────────────┐ │
│  │  // 文件内容预览（可折叠）        │ │
│  └──────────────────────────────────┘ │
└───────────────────────────────────────┘
```

#### 3.1.3 主动消息气泡

后端`proactive_message`事件推送的消息，用特殊样式区分：

```
┌─ 🔔 主动消息 ─────────────────────────┐
│  原因: 定时关怀                        │
│  "主人，已经3小时没休息了，要不要..."   │
│  [忽略] [回复]                         │
└────────────────────────────────────────┘
```

#### 3.1.4 情感指示器

在输入框旁显示当前情感分析结果：

```
  😊 开心 (0.8)  │  场景: 开发  │  [输入框...]
```

- **数据来源**：WS事件 `perception_update`

从当前App.tsx的useState碎片化迁移到Zustand统一Store：

```
src/frontend/src/stores/
├── useChatStore.ts          # 聊天状态（消息、输入、FC循环）

├── useEvolutionStore.ts     # 进化状态（四闭环、事件、指标）— 已有，需升级

├── useDesktopStore.ts       # 桌面代理状态（截图、OCR、操作历史）
├── useAutomationStore.ts    # 自动化状态（任务、触发器、模式）
├── useSecurityStore.ts      # 安全状态（日志、验证、审计）
├── useMonitorStore.ts       # 监控状态（资源、LLM、API指标）
├── useModelStore.ts         # 模型状态（列表、切换、健康）— 已有，需升级
├── useConnectionStore.ts    # 连接状态（WebSocket、在线状态）
└── useUIStore.ts            # UI状态（布局、面板、主题）
```
