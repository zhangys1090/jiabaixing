## 三、修复的问题描述

### P0-1: TypeScript 端 LoopController deprecated 但 AgentHarness 仍在使用

**问题描述**：

- TypeScript 端 `LoopController.ts` 已标记 `@deprecated`
- 但 `AgentHarness.ts` 仍在初始化和使用该组件
- 存在功能不一致风险

**修复方案**：

1. 更新 `LoopController.ts` 的 @deprecated 注释，添加详细废弃信息：
   - 废弃版本：V5.0
   - 迁移日期：2026-06-22
   - 预计移除版本：V6.0（约 2026-09）
   - 替代方案：使用 Python 后端
   - 回退方式：设置 AGENT_BACKEND=local
   - 维护状态：仅安全修复，不再新增功能

2. 在 `AgentHarness.ts` 顶部添加双后端架构说明：
   - 说明当 AGENT_BACKEND=python 时，LoopController 不会被使用
   - 说明废弃组件的状态和迁移计划

**验证结果**：

- ✅ 注释更新完成
- ✅ 双后端切换逻辑正确（在 bootstrap.ts 层面）
- ✅ 默认使用 Python 后端时，TS 端 LoopController 不会被调用
- ✅ 降级路径正确，AGENT_BACKEND=local 时仍可使用 TS 实现

### P1-2: 双后端编排层实现差异梳理

**问题描述**：

- TypeScript 端和 Python 端都有编排层实现
- 两套实现的功能范围和设计理念可能不同

**修复方案**：

1. 对比两端编排层实现
2. 列出差异点和各自的功能范围
3. 确认是否存在功能重复或缺失

**验证结果**：

- ✅ TypeScript 端编排层：
  - OrchestratorAgent - 顶层协调Agent
  - 面向Agent编排，基于LLM的目标拆解
  - 复杂度分析、扇出执行、结果聚合

- ✅ Python 端编排层：
  - OrchestrationExecutor - DAG任务执行器
  - 面向任务编排，支持DAG、并发控制、优先级、超时、重试
  - 更通用的任务调度器

- ✅ 差异分析：
  - 设计理念不同：TS端是Agent编排，Python端是任务编排
  - 应用场景不同：TS端用于复杂任务的Agent协作，Python端用于通用任务调度
  - 不存在直接的功能重复，而是互补关系
