一、本轮修复的重点问题

🔴 R-01　ReAct 思考解析器：嵌套 JSON 参数被截断（逻辑错误）

项内容
位置python/agent/loop/controller.py · _parse_react_thought() 原 L2669
问题旧正则 Args:\s*(\{.+?\}) 为非贪婪，遇首个 } 即截断。 对嵌套参数如 {"filters": {"type": "x"}} 会截为 {"filters": {"type": "x"}（非法 JSON）→ json.loads 失败 → tool_args = {}，真实工具参数被整体静默丢弃，导致带嵌套参数的工具调用必然失败。
风险高危 影响所有 ReAct 嵌套参数工具调用（搜索过滤、结构化入参等）
修复改为平衡括号扫描（跟踪 {/} 深度 + 字符串/转义状态），精确截取最外层 JSON 对象，再 json.loads。正确支持任意嵌套与字符串内含花括号。
验证新增回归测试 python/tests/test_react_parser.py（4 例：嵌套/扁平/字符串含花括号/无参数）全部通过；该测试在旧代码下必失败（锁定修复）。

🟡 R-02　memory/store.py 析构与关闭：静默吞错（错误被吞）

项内容
位置python/agent/memory/store.py · close() L1082、__del__() L1092
问题except Exception: pass 完全静默——向量库/SQLite 连接关闭失败（如句柄泄漏、写盘异常）无任何记录，运维不可见。
风险中 资源清理失败难以诊断（与首轮 P0-3 静默异常红线一致）
修复两处改为 except Exception as _exc: log_ignored(log, "...", _exc)，纳入项目既有静默异常基线。
验证ruff check 全绿；py_compile 通过。
